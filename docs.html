API Reference

接入文档

统一基础地址：https://api.example.invalid。可用模型与实际费率以模型广场和控制台为准。

认证

所有模型请求通过 HTTP Bearer Token 认证。用户登录后在“API 密钥”页面创建密钥。

Authorization header
Authorization: Bearer ${MODEL_API_KEY}

兼容端点

协议方法与路径用途
OpenAIPOST /v1/chat/completions对话补全兼容接口
OpenAIPOST /v1/responsesResponses API 兼容接口
OpenAIGET /v1/models查询当前密钥可用模型
AnthropicPOST /v1/messagesMessages API 兼容接口
Gemini/v1beta/*Gemini API 兼容路由

OpenAI 兼容示例

curl
curl https://api.example.invalid/v1/chat/completions \
  -H "Authorization: Bearer ${MODEL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": false
  }'

交给上游的接入清单

与上游确认时，请一次性收集以下信息。资料齐全后即可在管理后台完成账号和模型配置。

  1. 供应商名称、协议类型和正式 API Base URL。
  2. 鉴权方式：API Key、OAuth 或企业账户，以及密钥轮换规则。
  3. 正式模型 ID、别名、上下文长度、输入/输出能力和工具调用支持情况。
  4. 输入、输出、缓存、图片或其他计费单位的成本价。
  5. 单账号并发、RPM、TPM、日/月预算和配额重置时间。
  6. 流式响应、超时、重试、429 与 5xx 错误语义。
  7. 允许的客户类型、服务地区、转售授权与内容安全要求。
上游尚未发布的模型不要提前展示或售卖。模型广场仅应显示已经完成连通、计费和限流验收的模型。
